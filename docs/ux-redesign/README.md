## Per screen: what changes and why
Heights are the full-page height at 390px: before → after.

### 1. Tổng quan `/dashboard` (3,560 → ~2,400px)
- "Cần bạn xử lý" grouped by type (Học phí / Chăm sóc / Duyệt) with counts; one action per row, so 5 near-identical care tasks no longer bury everything else.
- Operational alerts become 4 severity tiles (icon + number + label) instead of unlabeled red digits.
- Revenue bars and branch table sit side by side on desktop; on mobile the secondary blocks (branches, teaching quality, reports) collapse into accordions.
- KPI strip keeps the 4 existing metrics, adds a delta chip; mobile = 2×2 grid.

### 2. Lịch dạy hôm nay (Giáo viên) `/teacher/home` (3,683 → ~2,900px)
- Each session shows one **stepper** (Check-in → Điểm danh → Bài giảng → Giao bài tập → Nộp báo cáo); only the current step is expanded with a single primary CTA, locked steps are compact chips (was: five equal cards, locked ones as dashed boxes).
- Time rail (17:30 / đến 19:00 / Ca chiều) gives the day's order at a glance; ended sessions collapse to one line.
- Mobile bottom tab bar + "+" action (ORDER) that no longer covers content or the tab bar.
- Overdue attendance list uses clear Còn 4 giờ / Quá 24h badges and one CTA per row.

### 3. Lập phiếu thu học phí `/tuition/receipts/create` (4,466 → ~2,400px)
- Desktop: 4 numbered steps on the left, **sticky summary panel** on the right (breakdown, big "Tổng thực thu", validation, Lưu nháp / Lưu & Gửi duyệt) — the money result is always visible.
- Student header + 4 stat cells replace the long info block; payment method is a segmented control with its notices inside.
- Mobile: accordion steps with "Bước 1/4", bottom bar with total + primary CTA (no floating bar over fields), 16px inputs.

### 4. Danh sách khách hàng (CRM) `/crm/customers` (3,038 → ~2,950px, first screen far lighter)
- One stage-chip scroller with counts (danger chip for "Chưa liên hệ >24h"), one search + 2 key filters, rest behind "Bộ lọc (n)".
- Table: phone as a link under the name, SLA on one line with icon + text, source never truncated, row actions Gọi / Xem / ⋯ instead of a lone pencil; bulk bar only when rows are selected.
- Mobile cards are compact (name + stage, SLA + tap-to-call, owner).

### 5. Chi tiết chấm công giáo viên `/payroll/timesheets/teachers` (5,531 → ~3,200px)
- Summary tiles first and clickable as filters (Chờ đối soát / Hợp lệ / Từ chối); filter bar compact with active-filter chips; "Chấm công theo lịch" is a collapsible banner with inline Xác nhận.
- Table grouped by date, single-line rows (ca, lớp, GV avatar, vào/ra vs lịch with delta chip, giờ, tình trạng, duyệt) instead of 3-line cells; "Chốt bảng công" lives in a bar at the table end.
- Mobile: filters behind "Bộ lọc (n)", date-grouped cards, "Xem thêm".

### 6. Việc cần duyệt `/approvals` (1,944 → ~1,600px)
- Header with total and urgency ("3 quá hạn"), count pills, requester avatar + amount (mono, right-aligned) + age badge on each row for fast scanning.
- Desktop master–detail: select a row to see key facts and **Duyệt / Từ chối** without leaving the list; bulk "Duyệt n mục" appears when ticked.
- Mobile: compact rows, 3 per group + "Xem tất cả", tap opens a detail sheet.

## Known limits
- Static mockups: interactions (tabs, drawer, accordions) are minimal HTML (`<details>`), not the real behaviour.
- Mobile "full page" PNGs show fixed bars (tab bar, bottom summary) inline at their DOM position; the `-screen` PNGs show the true first viewport.
- Pre-existing, not touched: `DemoPhase4Seeder` fails with a validation error when seeding a fresh DB (found while building the audit data).
- Next step needs owner approval of the direction; implementation would be Vue PRs per screen with tests.
